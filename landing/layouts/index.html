THE WORKFLOW 02 / 03

Inspect. Explain. Decide.

The tool gathers measurable signals, applies its published rubric, and reports the evidence behind each check.

01

Point it at a project

Analyze a local Git repository with a pyproject.toml. Release checks also inspect its PyPI history.

02

Review the checks

Inspect release, test, documentation, packaging, and maintenance evidence. Missing evidence appears as a failed check.

03

Use the result

Print a human report or JSON, validate the declared classifier in CI, or update the classifier in pyproject.toml.

TRY THE CLI
troml-dev-status analyze /path/to/project

THE RUBRIC 03 / 03

A classifier you can trace.

Checks are grouped by the evidence they inspect. The full rubric defines each threshold.

R / RELEASE

What shipped?

Published versions, artifacts, version metadata, and release activity.

Q / QUALITY

Can users verify it?

CI, tests, type hints, documentation, and changelog evidence.

C / SUPPLY CHAIN

Can it be reproduced?

Security policy, trusted publishing, dependency declarations, and lockfiles.

M / MAINTENANCE

Is it maintained?

Project age and recent movement in the source tree.

What this measures

Observable project artifacts. It does not judge support promises, budgets, or the stability of a Python API. Use the report as evidence for a decision, with the status mapping in view.
